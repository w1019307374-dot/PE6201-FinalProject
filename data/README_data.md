# Data explainer

## What this is
`complaints.csv` — 400 anonymised retail-bank customer-complaint tickets, each labelled
**ESCALATE** (200) or **MONITOR** (200).

## Source
Synthetic but realistic, generated by `code/make_data.py` (seed=42). Tickets are built from
12 complaint templates per class with varied amounts, locations and fees, then shuffled.
This keeps the data fully reproducible and free of any real PII — relevant under PDPA.

## Schema
| column | meaning |
|---|---|
| `text` | the customer ticket (free English text) |
| `label` | `ESCALATE` = fraud / missing money / locked account / legal threat; `MONITOR` = routine request |

## Train/test split
`part1.py` splits 75% train / 25% test stratified (300 train, 100 test). No test ticket appears
in any few-shot prompt — leakage is avoided by construction.

## Why synthetic
For a student project the priority is a labelled, reproducible, PII-free set on which to compare
the two approaches. A production system would swap in the bank's real historical tickets.
